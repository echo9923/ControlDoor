# 阶段 7 / 任务 07：队列缓冲、配置、测试与验收

## 目标

定义 ACS 实时事件与离线上传事件的队列缓冲策略、阶段 7 配置校验、自动化测试、真实设备联调和阶段通过标准。

## 队列缓冲策略

阶段 7 不做平台主动历史查询，也不存在历史补偿期间的专用实时缓冲。实时 ACS 事件和设备恢复后上传的离线 ACS 事件统一进入 `FaceEventIngestionService` 队列，后台消费者按接收顺序处理。

| 状态 | 行为 |
| --- | --- |
| 队列正常 | 实时事件和离线上传事件直接入队。 |
| 队列接近满 | 记录 `Warn`，继续投递。 |
| 队列已满 | 按配置丢弃或降级，并记录 `Error`。 |
| 服务停止 | 尽量处理已入队事件；未入队事件不持久化。 |

阶段 7 不新增事件暂存表。服务崩溃或队列溢出时，已进入设备离线缓存但尚未上传的事件仍依赖设备后续上传能力；已被服务端接收但未入队的事件无法保证恢复。

## 缓冲容量

如不新增配置，采用内部默认值：

| 项目 | 默认建议 |
| --- | --- |
| 全局队列容量 | 2000 条。 |
| 队列接近满阈值 | 80%。 |
| 超限策略 | 记录 `Error` 并丢弃新事件；如实现配置项，应保持默认行为明确。 |

如果新增配置项，必须同步主方案和配置模板。

## 配置校验

沿用 `FaceEventLogging`：

| 配置项 | 默认值 | 校验 |
| --- | --- | --- |
| `Enabled` | `true` | false 时不启动阶段 7 模块。 |
| `SnapshotRootDirectory` | `snapshots` | 不存在则创建，创建失败则模块不可用。 |
| `ExcludedDeviceIds` | `[]` | 只影响阶段 7 事件入库与离线上传补偿。 |
| `ExcludedDeviceIps` | `[]` | 只影响阶段 7 事件入库与离线上传补偿。 |
| `OfflineCompensationEnabled` | `true` | false 时忽略 `byCurrentEvent == 2` 的离线事件，普通实时事件仍处理。 |
| `AlarmDeployType` | `0` | 阶段 7 固定客户端布防；非法值回退为 `0` 或配置校验失败。 |
| `QueueCapacity` | `2000` | 小于最小值时使用默认值。 |

排除设备不影响设备连接、权限同步、设备管理，也不影响后续 AIOP 联动配置引用。

## 真实设备联调

真实设备联调必须显式开启，不纳入默认自动化测试。

| 联调项 | 操作 | 通过标准 |
| --- | --- | --- |
| ACS 实时回调 | 现场触发人脸识别或门禁认证。 | 收到 `COMM_ALARM_ACS`，队列有事件。 |
| 实时入库 | 触发一次有效认证。 | `attendance_gate_v2` 新增一条记录。 |
| 抓拍保存 | 触发带图片事件。 | `snapshots` 下生成图片，表中有路径。 |
| 重复保护 | 重放同一 mock 事件或设备重复上传同一离线事件。 | 不重复入库。 |
| 离线事件上传补偿 | 保持客户端布防，断开服务或网络期间触发事件，恢复后观察设备上传。 | 收到 `byCurrentEvent == 2` 的 `COMM_ALARM_ACS` 并入库。 |
| V50 连续回调 | 连续触发多次。 | 均能接收；如不能，启用 V31 兼容适配。 |

## 阶段 7 通过标准

事件处理失败时保留失败项，按 250ms 至 5s 的退避重试；批次中成功和明确无效的事件及时移除，缺失结果按失败保留。后台将失败事件及停止时尚未处理的事件写入运行目录 `data/acs-retry/`，启动后恢复处理，成功后删除对应文件。原始时间、员工标识、SDK 载荷和抓拍字节必须在恢复后保持一致，损坏文件保留为 `.invalid` 并记录错误。

该目录属于运行数据，服务账户必须可读写，升级和回滚时必须保留。写盘失败会记录错误并保留内存数据，但不能承诺磁盘故障或进程在事件首次处理前被强制终止时不丢失事件。队列容量仍有限，满队列拒绝项必须结合日志与设备离线上传补偿核查。

设备流水 ID 保持原有可表示范围内的映射；超出范围时使用包含设备 ID 和流水的稳定摘要，避免溢出后只保留流水造成跨设备固定碰撞。

| 标准 | 说明 |
| --- | --- |
| 实时链路完整 | ACS 回调到数据库入库端到端可验证。 |
| 离线上传链路完整 | 设备恢复后上传的离线事件可识别、入队并入库。 |
| 主动查询未启用 | 阶段 7 不调用历史 ACS 查询，不维护 checkpoint。 |
| 重复保护稳定 | 实时重复、离线上传重复均不重复写表。 |
| 图片策略清楚 | 成功保存、失败降级、路径长度都有处理。 |
| 回调线程安全 | 不在 SDK 回调线程写库写文件。 |
| 排除设备生效 | 配置排除只影响阶段 7 事件能力。 |
| 数据库零结构变更 | 不修改现有表结构，不新增阶段 7 表。 |

## 代码复核更新（2026-09-07，R02/R04）

- 消费循环改为 drain 取件：队列有积压时连续取到批次上限，仅在队列空且未到刷新期限时等待，消除逐条 20ms 等待的限速。
- 失败事件隔离：新事件（活动批次）与到期重试（重试道，250ms→5s 指数退避、每轮参与量以批次大小为预算）分开处理；失败不再占住活动批次。
- 死信区：重试次数耗尽（默认 10 次）或不可恢复失败（`DATABASE_FAILURE`/`FAILED`）的事件写入重试目录 `dead-letter/` 子目录（含失败原因），不自动重放；运维确认修复后把文件移回重试目录即可重放。死信文件以 `dl-` 前缀与源重试文件名配对实现幂等转移：源文件删除失败（如被占用）时不重新投递业务、不重复生成死信，重启后同样凭配对文件识别；占用解除后由磁盘回放轮次自动补清理遗留源文件。
- 磁盘回放逐文件容错：单个重试文件瞬时 I/O 故障（如被占用）只跳过该文件，本轮其余事件照常加载交付，下一轮重试该文件；瞬时 I/O 异常不按 JSON 损坏处理为 `.invalid`。
- 环境故障保护：整轮全部以同一非重试错误失败（如缺表）时按可重试退避处理，不会把整个事件流死信。
- 永久校验失败白名单补入仓储校验码 `INVALID`。
- 停止/重启语义不变：`PersistPending` 覆盖活动批次、重试道与队列剩余；重启后经重试文件恢复（重试计数重置）。
- `FaceEventLogging.BatchSize` 新增校验范围 1~1000（服务内同步收敛），`FlushIntervalMs` 最小 10ms。

## 验收复核更新（2026-09-07，F01）

- 到期重试与新事件轮流使用完整批次预算：存在到期重试的轮次由重试独占（`BatchSize=1` 也保证公平），下一轮回到新事件，持续满批流量下既有失败事件仍能在退避间隔后重试，新事件也不被重试流量反向阻塞。
- 重试道容量上限与队列容量一致：达上限后暂停从队列取件，队列以 `QUEUE_FULL` 形成背压，持续故障下内存保持有界（总量上界为队列容量+批次大小）；故障恢复后自动排空。

## 第三轮验收更新（2026-09-07，G1）

- 重试独占轮的结果处理不再以活动批次实时长度做删除守卫，改用本轮批次贡献数快照：重试结果只更新其重试条目，绝不删除活动批次中尚未处理的新事件（修复"重试轮误删新事件导致已接受事件丢失"）。

## 扩展复核更新（2026-09-07，H2/H3）

- 磁盘回放与实时取件使用同一内存准入预算：重试道达到队列容量后不再从磁盘加载事件，剩余事件保留在磁盘，由到期重试/死信释放名额后继续加载；重启后的内存占用不随磁盘积压增长。
- 到期重试与新事件按来源轮换：双方都有待处理内容时交替获得完整轮次（`BatchSize=1` 亦然），持续到期重试不再连续阻塞新事件，持续新流量也不再饿死重试。

## 代码复核更新（2026-09-09，J2/J3）

- 死信源文件补清理成功后同步解除内存登记（新增路径 → 事件反向索引）：此前只删磁盘文件，已死信事件的图片字节引用会随登记长期滞留（J2）。
- 磁盘回放改为惰性枚举、达到本批预算立即停止目录遍历，不再为死信配对扫描整个重试目录（J3）：数千文件积压时每批只读取需要的数量。
- 新增独立死信巡检 `Patrol`（配置 `FaceEventLogging.DeadLetterPatrolIntervalMs`，默认 30 秒）：在批处理锁外周期补清理死信遗留源文件，并统计死信目录文件数输出告警，作为死信数量监控指标。
