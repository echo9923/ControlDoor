# ControlDoor 部署说明

## 发布包位置

现场发布包固定使用：

```text
门禁publish\ServicePackage
```

该目录必须包含：

```text
ControlDoor.exe
ControlDoor.exe.config
Configuration\appsettings.json
Configuration\devices.json
tools\service\common-service.ps1
tools\service\install-service.ps1
tools\service\start-service.ps1
tools\service\stop-service.ps1
tools\service\uninstall-service.ps1
logs\
snapshots\
docs\
```

`logs\` 和 `snapshots\` 为空目录占位，用于发布包结构兼容；默认运行期日志、SDK 日志和抓拍照片分别写入 `D:\ControlDoorData\logs`、`D:\ControlDoorData\logs\sdk` 和 `D:\ControlDoorData\snapshots`。如现场需要其它位置，请在 `Configuration\appsettings.json` 中修改 `Logging.LogDirectory`、`HikvisionSdk.SdkLogDirectory` 和 `FaceEventLogging.SnapshotRootDirectory`。

## 安装前步骤

1. 确认 Hikvision SDK DLL 与进程位数一致。
2. 确认 `HCNetSDK.dll` 位于 exe 同级或 `sdk\Hikvision\HCNetSDK.dll`。
3. 确认 `SqlServerTypes` 位于 exe 同级或 `sdk\SqlServerTypes`。
4. 修改 `Configuration\appsettings.json` 中的数据库、端口、日志和 `Devices.FilePath` 等配置。
5. 修改 `Configuration\devices.json` 中的设备清单；每台设备必须包含 `deviceId`、`name`、`types`、`ipAddress`、`port`、`username`、`password`、`enabled`、`remark`。
6. 正式部署建议保持 `Devices.Items` 为空，通过 `Configuration\devices.json` 或设备管理 gRPC 维护设备。若使用内联 `Devices.Items`，`AddDevice`/`DeleteDevice` 只更新当前运行时缓存，不写文件。
7. 升级已有服务时先停止旧进程，再在 Docker 数据库中执行 `database/专项_20260309_设备操作重试状态表.sql`。该脚本幂等补齐 `intent_version`，保留原有补偿记录；新版上线后不要同时运行仍按旧规则回写补偿状态的旧进程。
8. 执行 `ControlDoor.exe --validate-config`，必须通过后再安装服务。

## 服务脚本

```powershell
powershell -ExecutionPolicy Bypass -File tools\service\install-service.ps1 -PackageRoot .
powershell -ExecutionPolicy Bypass -File tools\service\start-service.ps1 -PackageRoot .
powershell -ExecutionPolicy Bypass -File tools\service\stop-service.ps1
powershell -ExecutionPolicy Bypass -File tools\service\uninstall-service.ps1
```

服务名和显示名固定为 `ControlDoor`。卸载脚本只移除 Windows Service，不删除配置、日志、抓拍和数据库数据。

## 日志查看与升级

日常查看 `D:\ControlDoorData\logs\ControlDoor-yyyyMMdd.log`，默认只呈现服务启停、设备上下线、业务批次结果、门禁联动和异常。诊断文件位于 `D:\ControlDoorData\logs\diagnostic\ControlDoor-diagnostic-yyyyMMdd.log`，持续记录内部过程和脱敏报文。文件达到 20MB 后追加 `-001` 等序号；查询时应同时包含滚动文件。

1. 从日常日志定位时间、设备、员工、操作和 `requestId`。
2. 在对应时间段的诊断文件中搜索相同 `requestId`，查看报文、设备任务、SDK 结果、错误码和堆栈。
3. 离线补偿会生成新的扫描请求编号，应结合设备、员工、`stateId` 和 `intentVersion` 查询。原请求编号没有新增数据库持久化字段，不能假定跨服务重启仍沿用原请求编号。

默认日常日志最多保留 30 天、512MB，诊断日志最多保留 7 天、2GB，先达到的限制生效。详细报文默认隐藏密码、API Key 和人脸 Base64 原文。已有部署升级时，核对并合并新日志配置，将 `IncludeCredentialFields` 和 `IncludeFaceImageBase64` 设为 `false`；缺失的新配置项使用默认值，原来显式设置的值仍然有效。配置变更需重启服务，停服后、重新启动前通过 `--validate-config` 输出核对路径和策略，避免运行中的服务占用端口导致检查失败。

日常日志改为中文单行格式，自动化解析脚本应改读保留键值格式的诊断文件。旧文件保留至正常清理到期；若升级当天已有旧格式日志，该日常文件可能同时包含升级前后的行格式。两份应用日志的限额不管理海康原生日志目录。

## 回滚步骤

启用 ACS 事件后，运行目录 `data\acs-retry\` 保存尚未入库的事件和抓拍载荷。服务账户需对该目录有读写权限；部署、升级和回滚不得覆盖或删除该目录。停止超时表示后台仍可能在等待 SDK 调用结束，不表示清理完成，应确认旧进程退出后再启动新版本。

1. 执行 `tools\service\stop-service.ps1` 停止当前服务。
2. 备份当前 `ServicePackage`、`Configuration\appsettings.json` 和 `Configuration\devices.json`。
3. 恢复上一版 `ServicePackage` 和上一版配置。
4. 执行 `ControlDoor.exe --validate-config`。
5. 执行 `tools\service\start-service.ps1` 启动旧版本。
