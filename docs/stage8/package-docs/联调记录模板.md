## 代码复核更新（2026-09-09，R4）

- 联调观察指标新增（对应问题清单第 6 节建议，服务日志可直接检索）：
  - `DeviceWorker` 的 `queueWaitMs` 字段：每条设备任务的排队等待；超过 `DeviceSdkDispatcher.SlowQueueWaitWarningMs`（默认 5 秒）输出"设备任务排队等待过长"告警（低优先级健康检查豁免）。
  - `DeviceWorkerStats` 周期日志（默认每 60 秒）：每工作通道的队列深度、最老排队任务年龄、完成/失败/取消累计与当前执行中操作。
  - `ScanRetryStates` 补偿扫描日志的 `due`/`submitted`/`offlineDeferred`（K3 语义：仅在线过滤后的实际处理量）。
  - `DeadLetterPatrol` 死信巡检日志的 `deadLetterCount`（>0 时告警并提示 `--replay-dead-letters`）。
  - `FaceEventIngestion` 的 `QUEUE_FULL_PERSISTED`/`OVERFLOW_FULL`（R1 溢出兜底与最终边界）。
  - `SnapshotCleanup` 的 `deletedFiles`/`deletedBytes`（R3，启用保留期后）。
- 以上指标必须与具体业务结果关联核对（如"排队等待长"对应哪个批量下发、哪台慢设备），避免只看服务在线。
